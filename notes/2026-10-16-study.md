## 0. 자료형의 분류 (강의 장표)

같은 타입을 **세 가지 관점**으로 나눈다. (접근 / 변경 / 저장)

### 0-1. 접근 방법

| 분류 | 의미 | 타입 |
|------|------|------|
| **직접(Direct)** | 값 하나 자체. 인덱스로 “몇 번째”를 고르지 않음 | `int`, `float`, `complex`, `bool` |
| **시퀀스(Sequence)** | **순서**가 있고, 인덱스로 접근 (`a[0]`) | `bytes`, `str`, `list`, `tuple` |
| **매핑(Mapping)** | **키 → 값**. `d["이름"]`처럼 키로 접근 | `dict` |

```python
# Direct: 값 하나
n = 10

# Sequence: 순서 + 인덱스
s = "hi"          # s[0] → 'h'
t = (1, 2, 3)     # t[1] → 2

# Mapping: 키로 접근
d = {"name": "Kim"}  # d["name"] → "Kim"
```

> 장표에 `set`은 접근 방법에 안 나와 있다.  
> `set`은 **순서·인덱스·키 없음** → Direct/Sequence/Mapping 어디에도 안 넣고,  
> 보통 “집합(Set)”으로 따로 둔다. (변경·저장 쪽에는 등장)

### 0-2. 변경 가능성

| 분류 | 의미 | 타입 |
|------|------|------|
| **변경가능(Mutable)** | **같은 객체** 안을 고칠 수 있음 | `list`, `set`, `dict` |
| **변경불가능(Immutable)** | 객체 내용 수정 불가. “바꾸려면” **새 객체**를 만들고 이름만 다시 붙임 | `int`, `float`, `complex`, `bool`, `bytes`, `str`, `tuple` |

```python
# Mutable: 같은 list를 수정
a = [1, 2, 3]
a[0] = 100          # OK → [100, 2, 3]

# Immutable: 튜플/문자열은 수정 불가
t = (1, 2, 3)
# t[0] = 100        # TypeError

s = "hi"
# s[0] = "H"        # TypeError
s = "Hi"            # 재할당(새 문자열을 가리킴)은 OK
```

→ 4절 **재할당 vs 수정**, `pr_6`/`pr_7`과 바로 연결된다.

### 0-3. 저장 모델

| 분류 | 의미 | 타입 |
|------|------|------|
| **리터럴(Literal)** | 코드에 값을 **그대로 적는** 형태. “값 자체”에 가깝다 | `int`, `float`, `complex`, `bool`, `bytes`, `str` |
| **저장(Container)** | **다른 객체를 담는** 그릇 | `list`, `tuple`, `dict`, `set` |

```python
# Literal: 값 자체를 적음
x = 42
y = 3.14
z = "hello"

# Container: 다른 객체를 담음
nums = [1, 2, 3]           # list가 int들을 담음
pair = (10, 20)            # tuple이 int들을 담음
info = {"age": 20}         # dict가 키·값을 담음
uniq = {1, 2, 3}           # set이 원소들을 담음
```

### 0-4. 한눈에 겹쳐 보기

| 타입 | 접근 | 변경 | 저장 |
|------|------|------|------|
| `int` / `float` / `complex` / `bool` | Direct | Immutable | Literal |
| `str` / `bytes` | Sequence | Immutable | Literal |
| `tuple` | Sequence | Immutable | Container |
| `list` | Sequence | **Mutable** | Container |
| `dict` | Mapping | **Mutable** | Container |
| `set` | (집합, 별도) | **Mutable** | Container |

### 0-5. 장표에서 기억할 포인트

1. **시퀀스** = 순서 + 인덱스. **매핑** = 키.
2. **Mutable**만 “안을 고칠” 수 있고, Immutable은 **재할당**만.
3. **Container**는 다른 객체를 담는다 → 변수=이름표·참조 이야기와 연결.
4. `list`/`tuple`은 둘 다 시퀀스·컨테이너지만, **변경 가능 여부**만 다르다. (`pr_6`)

### 0-6. 인덱싱과 슬라이싱 (시퀀스 공통)

시퀀스(`str`, `list`, `tuple`, `bytes`)는 **위치 번호(인덱스)** 로 원소를 꺼낸다.

#### 인덱싱 — 하나 고르기

```
인덱스:  0  1  2  3  4
문자:    P  y  t  h  o   ← s = "Python" 이면 길이 6, 마지막은 n(5)
음수:   -6 -5 -4 -3 -2 -1
```

```python
s = "Python"
s[0]    # 'P'   처음부터
s[2]    # 't'
s[-1]   # 'n'   끝에서 첫 번째
s[-2]   # 'o'

# 없는 번호 → IndexError
# s[100]
```

- **0부터** 센다.
- **음수** = 끝에서부터 (`-1`이 마지막).
- `dict`/`set`에는 인덱싱 없음 (키가 아니거나 순서 없음).

#### 슬라이싱 — 구간 자르기

형식: `시퀀스[시작:끝:간격]`  
→ **시작 포함, 끝 미포함**. 비운 칸은 “처음부터 / 끝까지 / 1칸씩”.

```python
s = "Python"
s[0:2]     # 'Py'     0,1 (2는 안 들어감)
s[2:]      # 'thon'   2부터 끝까지
s[:4]      # 'Pyth'   처음부터 3까지
s[:]       # 'Python' 전체 복사에 가깝게
s[::2]     # 'Pto'    한 칸씩 건너뛰기
s[::-1]    # 'nohtyP' 뒤집기
s[-3:]     # 'hon'    끝 3글자
```

리스트도 같다:

```python
a = [10, 20, 30, 40, 50]
a[1:4]     # [20, 30, 40]
a[::2]     # [10, 30, 50]
```

| | 인덱싱 `a[i]` | 슬라이싱 `a[i:j]` |
|--|---------------|-------------------|
| 결과 | 원소 **하나** | **같은 종류**의 시퀀스 (부분) |
| 범위 밖 | `IndexError` | 에러 없이 가능한 만큼만 |
| 수정 | `list`만 `a[i]=…` 가능 | `list`만 `a[i:j]=…` 가능. `str`/`tuple`은 불가 |

```python
# 슬라이싱은 범위 밖이어도 안전
s = "hi"
s[0:100]   # 'hi'  (IndexError 아님)
s[100]     # IndexError
```

## 3. 리스트 vs 튜플 (`pr_6.py`) — 핵심

| | 리스트 | 튜플 |
|---|---|---|
| 표기 | `[1, 2, 3]` | `(1, 2, 3)` |
| 변경 | 가능 (mutable) | **불가** (immutable) |
| 용도 | 자주 바뀌는 목록 | 좌표·RGB 등 고정 묶음 |

- 원소 1개 튜플: `(90,)` — `(90)`만 쓰면 그냥 숫자.
- 튜플을 “못 고치는” 이유: **불변으로 설계** (실수 방지, 딕셔너리 키, 안전).
- 변환: `tuple(list)`, `list(tuple)`.

## 4. 변수 = 이름표 (상자 아님) (`pr_7.py`) — 오늘의 핵심 정리

### 결론 (강의 상자 비유와 구분)

강사님께서 “`a`에 할당된 공간에 `1`이 있다가 `"1"`이 들어온다”고 하신 것은  
**상자(고정 칸) 비유**에 가깝고, **Python 실제 동작은 이름표(참조) 모델**이 맞다.

```python
a = 1      # 이름 a ──→ 정수 객체 1
a = "1"    # 이름 a ──→ 문자열 객체 "1"  (같은 칸을 덮어쓰는 게 아님)
```

확인:

```python
a = 1
print(id(a), type(a))
a = "1"
print(id(a), type(a))  # id가 바뀜 → 다른 객체
```

### 재할당 vs 수정

| 용어 | 의미 | 예 |
|------|------|-----|
| **재할당** | 이름이 **다른 객체**를 가리킴 | `a = (10, 2, 3)` |
| **수정** | **같은 객체** 안을 바꿈 | `list_a[0] = 100` |

### 참조·GC (튜플/변수 공통)

```python
a = (1, 2, 3)
b = a              # 같은 객체를 같이 가리킴 (복사 아님)
a = (10, 2, 3)     # a만 이동. b는 여전히 (1,2,3). 튜플은 "수정"된 적 없음
b = a              # b도 (10,2,3)으로. (1,2,3) 참조 0개 → GC 대상
```

- 가리키는 이름이 있으면 메모리에 **유지**.
- 참조가 0이 되면 **회수 가능** (당장 삭제가 아니라 GC가 나중에 처리).
- 리스트를 **수정**하면 공유하던 `list_b`도 같이 바뀜.  
  `list_a = [새리스트]`처럼 **재할당**하면 `list_b`는 예전 리스트를 유지.
