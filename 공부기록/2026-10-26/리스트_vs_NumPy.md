# 리스트 vs NumPy 배열

> 2026-10-26 NumPy 입문 — 예제 들어가기 전 개념 정리

핵심만 말하면, **리스트는 “여러 종류를 담는 상자”**, **NumPy 배열은 “같은 종류 숫자를 빠르게 계산하는 표”**에 가깝다.

---

## 한눈에 비교

| | 리스트 (`list`) | NumPy 배열 (`ndarray`) |
|--|----------------|------------------------|
| 담는 것 | 뭐든 섞여도 됨 (`[1, "a", True]`) | 보통 **같은 타입** (전부 int/float) |
| 계산 | `for`로 하나씩 | **통째로** 연산 (`a * 2`) |
| 속도 | 느린 편 (파이썬 루프) | 빠른 편 (내부 C 연산) |
| 형태 | 1차원에 가깝게 씀 | 1차원·2차원·다차원 **행렬**처럼 |
| 크기 | `append`로 늘리기 쉬움 | 크기 고정에 가깝고, 바꾸면 새 배열을 만드는 경우가 많음 |

---

## 체감 예시

### 리스트 — “하나씩 손으로”

```python
a = [1, 2, 3]
b = [x * 2 for x in a]   # 직접 돌면서 만듦
```

### NumPy — “배열 전체에 한 번에”

```python
import numpy as np

a = np.array([1, 2, 3])
b = a * 2                 # [2, 4, 6] 바로 나옴
```

### 헷갈리기 쉬운 점: `* 2`의 의미

| 코드 | 결과 | 의미 |
|------|------|------|
| `[1, 2, 3] * 2` | `[1, 2, 3, 1, 2, 3]` | 리스트가 **두 번 이어짐** |
| `np.array([1, 2, 3]) * 2` | `[2, 4, 6]` | **원소마다** 곱함 |

강사가 여기서 차이를 많이 강조하는 경우가 많다.

---

## 언제 뭐 쓰나

| 상황 | 추천 |
|------|------|
| 이름·설정·타입이 섞인 데이터 | **리스트** |
| 길이가 자주 바뀌는 일반 프로그램 | **리스트** |
| 점수·센서·이미지처럼 숫자가 많음 | **NumPy** |
| 합·평균·행렬 계산 | **NumPy** |

실무 흐름 예: 리스트로 모은 뒤 → 계산할 때 `np.array(...)`로 변환.

---

## 비유

- **리스트** = 장바구니  
  사과·우유·메모를 섞어 넣어도 됨. 계산은 계산대에서 하나씩.
- **NumPy** = 엑셀 표 / 계산기 묶음  
  칸마다 같은 종류의 숫자. `×2`를 한 번에 적용.

그래서 데이터 분석·AI 쪽은 리스트로 모아 두고, 계산할 때 NumPy로 넘기는 패턴이 흔하다.
