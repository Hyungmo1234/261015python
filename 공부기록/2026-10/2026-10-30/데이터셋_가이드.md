## 1. 커리큘럼과 데이터 매핑

과정 표의 세부주제는 이미 `물류 자동화 / 엘리베이터 / 공정 설비`로 갈라져 있습니다. 둘 다 지원할 때는 공개 데이터가 많고, 192시간 캡스톤까지 이어지는 **물류·이송**을 고릅니다.

| 프로젝트 | 시간 | 표의 과제 | 메인 데이터 | 보조 |
|---|---|---|---|---|
| **I** 설비 운영 데이터 이상탐지·예측 | 56 | 물류 장애패턴 / 엘리베이터 운행로그 유지보수예측 | `data.csv`로 파이프라인 구축 → AI-Hub OHT/AGV 센서로 이전 | Huawei 엘리베이터 도어, AI4I 2020, KAMP 회전기계 |
| **II** 컴퓨터 비전 | 56 | 생산라인 불량 / 물류 이송·분류 객체인식 | **MVTec AD** (`cable`, `metal_nut`, `screw`, `transistor`) | NEU Surface Defect, KolektorSDD2, AI-Hub SMT |
| **III** 현장 RAG 어시스턴트 | 64 | 유지보수 RAG / 매뉴얼 챗봇 / 장애 이력 트러블슈팅 | I 예측결과 CSV + 공개 정비 매뉴얼 | KAMP 가이드북, Mitsubishi/ASME MCP |
| **IV** 멀티모달 캡스톤 | 192 | 영상+센서 융합 / 로그+이미지+문서 품질진단 | **AI-Hub OHT/AGV 센서+열화상** | I+II+III를 붙인 대시보드 |

I에서 만들 산출물(이상점수, 열화 등급, 원인 리포트)이 III·IV의 입력이 되어야 합니다.

## 2. 프로젝트별 추천 데이터셋

### 프로젝트 I — 이상탐지·고장예측

1. **지금 있는 파일:** `data.csv`  
   Hugging Face [Petsteb/industrial-sensor-anomaly-data](https://huggingface.co/datasets/Petsteb/industrial-sensor-anomaly-data)  
   합성 다변량 센서, 5대 설비, 1분 간격 7일, 이상 4.6%. 상세 평가는 아래 4절.
2. **메인(현장 스토리):** [AI-Hub 제조현장 이송장치 열화 예지보전](https://www.aihub.or.kr/aihubdata/data/view.do?dataSetSn=71802)  
   OHT·AGV, 전류/온도/분진 + 열화상, 라벨 정상/관심/경고/위험. 신청에 며칠 걸림.
3. **엘리베이터 보조:** [Huawei 엘리베이터 도어](https://www.kaggle.com/datasets/shivamb/elevator-predictive-maintenance-dataset)  
   베어링·습도·진동 4Hz. 타깃은 보통 진동 회귀.
4. **입문용:** [AI4I 2020](https://archive.ics.uci.edu/dataset/601/ai4i+2020+predictive+maintenance+dataset) — 표 1만행, 고장모드 5종.
5. **진동 깊이:** [CWRU Bearing](https://engineering.case.edu/bearingdatacenter), [KAMP 회전기계](https://www.kamp-ai.kr/), [IMS Bearing](https://phm-datasets.s3.amazonaws.com/NASA/4.+Bearings.zip)

### 프로젝트 II — 컴퓨터 비전

- **메인:** [MVTec AD](https://www.mvtec.com/research-teaching/datasets/mvtec-ad) — 양품만 학습 → 불량 탐지. 산업 비전 면접에서 가장 잘 통함.
- 불량 **유형 분류:** [NEU Surface Defect](https://www.kaggle.com/datasets/kaustubhdikshit/neu-surface-defect-database)
- 실제 라인 스크래치: [KolektorSDD2](https://www.vicos.si/resources/kolektorsdd2/)
- SMT·AOI: [AI-Hub SMT 멀티모달](https://www.aihub.or.kr/aihubdata/data/view.do?dataSetSn=71900)

엘리베이터 탑승 CCTV는 쓸 만한 공개셋이 거의 없습니다. II는 품질검사 비전으로 가고, 엘리베이터는 I·III에 둡니다.

### 프로젝트 III — RAG

유명한 표 데이터가 아니라 **문서 코퍼스 + I의 예측결과**가 핵심입니다.

- [Mitsubishi 엘리베이터 정비 매뉴얼](https://www.mebs.com/resources/owners/)
- [ASME MCP 정비절차](https://www.easternelevator.com/wp-content/uploads/2022/01/MCP-Maintenance-Procedures.Rev1_.072019.pdf)
- [ElevatorCalc 매뉴얼 모음](https://elevatorcalc.com/manuals)
- KAMP 데이터셋 가이드북
- I 출력: `설비ID, 시간, 이상점수, 예측등급, 주요센서`

데모 질문 예: “AGV 전류가 오르고 열화상이 경고면 뭐부터 점검하지?” / “도어 진동이 갑자기 커지면 어떤 정비 항목을 봐야 하지?”

### 프로젝트 IV — 멀티모달 캡스톤

[AI-Hub 이송장치 열화 예지보전](https://www.aihub.or.kr/aihubdata/data/view.do?dataSetSn=71802) — 1세트 = 센서 8종 + 열화상 1장.

구성: I 시계열 + II 이미지 이상탐지 + 융합 등급예측 + III RAG 설명 + 대시보드.

## 4. 보유 데이터 `data.csv` 평가

출처: [Petsteb/industrial-sensor-anomaly-data](https://huggingface.co/datasets/Petsteb/industrial-sensor-anomaly-data) (MIT, 합성, seed=42)

### 한 줄 결론

**프로젝트 I 연습용으로는 좋습니다.** 스키마가 현장 센서와 비슷하고, 결측·불균형·드리프트·누수 컬럼이 의도적으로 들어 있어 “파이프라인을 제대로 짰다”를 보여주기 좋습니다.  
다만 **실공장/엘리베이터/AGV 데이터가 아닙니다.** 면접에서는 “합성 벤치마크로 이상탐지 파이프라인을 검증한 뒤, AI-Hub 이송장치 데이터로 옮긴다”고 말하세요.

### 구성

| 항목 | 값 |
|---|---|
| 행 × 열 | 50,000 × 22 |
| 설비 | EQ-001 ~ EQ-005, 각 10,000행 |
| 기간 | 2024-01-01 00:00 ~ 2024-01-07 22:39, **1분 간격, 결측 구간 없음** |
| 이상 비율 | 2,295건 (4.59%) |
| 라벨 정합 | `is_anomaly` ↔ `anomaly_type` 불일치 0건 |

**센서 11종:** 온도, 진동, 압력, RPM, 유량, 전력, 냉각수온, 음향, 오일점도, 습도, 외기온  
**메타:** 설비수명, 정비 후 경과시간, 운전모드  
**타깃:** `is_anomaly`, `anomaly_type`

### 이상 유형 (생성기가 심어 둔 패턴)

| 유형 | 건수 | 센서에서 실제로 보이는 것 |
|---|---|---|
| thermal_runaway | 673 | 온도 평균 117.8°C (정상 109.9), 점도 하락 |
| pressure_leak | 622 | 압력 143.5 kPa (정상 150.4) |
| bearing_degradation | 522 | 진동 0.75 mm/s (정상 0.23), 음향 85 dB (정상 73) |
| sensor_malfunction | 478 | 한 채널만 튀고 상관 센서는 정상. 음수 온도/진동이 여기 섞여 있음 |

운전모드: `normal` 41,915 / `high_load` 5,163 / `idle` 1,321 / `cooldown` 1,000 / `startup` 601.  
startup 구간 이상은 0건. idle·cooldown에서 이상 비율이 조금 더 높음.

### 품질 — 잘 된 점

- 설비·시간 균형이 깨끗함 (5대 × 10,000, 60초 격자)
- 모드별로 센서 베이스라인이 다름 (idle RPM ~294, high_load ~3,610). 모드를 무시하면 오탐이 납니다.
- 결측 1.3~2.7%/컬럼, 행 기준 약 16%가 센서 NA 하나 이상. 무작위 + 블록 결측이 섞여 있음.
- 설비 나이 차이: EQ-003 ~1,400h, EQ-004 ~5,075h. 설비별 모델/도메인 적응을 말할 수 있음.

### 품질 — 반드시 처리할 함정

제작자가 **타깃 누수 3개**를 넣어 두었습니다. 예측 시점에는 없는 값입니다.

| 컬럼 | `is_anomaly`와 상관 | 쓰면 안 되는 이유 |
|---|---|---|
| `rolling_anomaly_rate` | 0.71 | 라벨의 중심 이동평균 |
| `maintenance_priority_score` | 0.64 | 이상 여부로 사후 부여. 정상 평균 15, 이상 평균 50 |
| `alert_code` | 사실상 라벨 | `PRESS_CRIT`/`VIB_CRIT`/`TEMP_CRIT`/`SENSOR_ERR`는 전부 이상. `NONE`이어도 이상 170건 |

학습 피처에서 이 셋과 `anomaly_type`을 **반드시 제거**하세요. 넣으면 AUC가 비정상적으로 높고, 면접에서 바로 지적받습니다.

기타:

- 온도 min **-192°C**, 진동 min **-0.74 mm/s**, 온도 max 389°C → 물리적으로 불가능. `sensor_malfunction` 또는 노이즈로 취급.
- 설비별 전반부 vs 후반부 온도가 **+55~62°C** 이동. 시계열을 랜덤 셔플하면 드리프트를 못 봅니다. **시간 순서 split** (앞 5일 train / 뒤 2일 test 등).
- `TEMP_WARN` 2,107건 중 1,909건은 정상. 알람 ≠ 이상.

### 프로젝트 I에서 쓰는 방법

1. 누수 컬럼 3개 제거
2. 설비·시간 기준 분할 (랜덤 split 금지)
3. 결측: 전방 채움 + 결측 마스크
4. 운전모드 one-hot 또는 모드별 잔차
5. 과제 A: `is_anomaly` 이진 이상탐지 (Isolation Forest / Autoencoder vs 지도학습)
6. 과제 B: `anomaly_type` 다중분류. `sensor_malfunction`은 “설비가 아니라 센서가 고장”이라 조치가 다름 → 면접에서 강한 포인트
7. 산출: 설비×시간 이상점수, 유형, 근거 센서. 이것을 III RAG 입력으로 넘김
